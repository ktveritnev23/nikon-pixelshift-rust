# План: электронная стабилизация + крупно-сдвиговое выравнивание + медленное движение + косметика fallback-зон

## Часть 1 — пирамидальный поиск в выравнивателе (устраняет провал на тряске)

Точка провала: `measure()` берёт глобальную оценку из центрального окна через `coarse_shift` с радиусом ±4 решёточных px (±8 сенсорных) вокруг (0,0) — ручная тряска даёт 5–22 px, оценка не находится, Гаусс–Ньютон проваливается (residual до 9 px, conf=0).

- `src/shift.rs`:
  - `fn decimate(plane, factor) -> Plane` — box-усреднение (решётка ужеblur-нута, безопасно);
  - `coarse_shift` получает параметр радиуса (сейчас константа);
  - новая структура `GlobalPrep { coarse: Plane }` — вся рамка референса, решётка /8 (≈378×252), строится один раз на серию рядом с `build_preps`;
  - `measure()`: глобальная инициализация = NCC на грубом уровне в диапазоне ±16 грубых px (±128 сенсорных — с запасом над наблюдаемыми 22 px), результат округляется и передаётся в существующий путь (центральное окно → окна → `fit_rigid`). Каскад «пирамида → окно → GN» сохраняет текущую точность 0.02 px на малых сдвигах (поведение идентично, когда сдвиг мал — просто шире воронка поиска);
  - `estimate()` (одна пара, используется цепочкой перепривязки) идёт через тот же путь.
- Поиск пирамидой включён **всегда** (это строгая робастность: на малых сдвигах находит тот же минимум); опция пользователя управляет только кропом.
- Границы/риски: глобальный NCC по всей рамке устойчив к локальному движению; защита от ложной фиксации — те же outlier-окна `fit_rigid`.

## Часть 2 — опция «Электронная стабилизация» (кроп по пересечению)

- `MergeParams.stabilize: bool` (default false). В `merge()`: если включено — прямоугольник пересечения покрытий всех используемых кадров в координатах референса: для каждого кадра углы рамки через `inverse_map` (жёсткая модель), AABB, ужимка на максимальное смещение углов от поворота; пересечение по всем кадрам; кроп плоскостей/cov готовыми `crop_plane`/`crop_bytes` (по образцу `crop_uncovered`, merge.rs:226–254). Механизм согласуется с `crop_uncovered` (порядок: стабилизация → coverage-trim).
- Разводка: `EditOptions.stabilize` → GUI-чекбокс «Электронная стабилизация» / "Electronic stabilization" (вкладка «Параметры», рядом с масштабом — влияет на следующее «Объединить», как `align`); CLI `--stabilize`; `inspect --stabilize` печатает, каким был бы кроп; сводки CLI/GUI печатают итоговый размер и величину кропа.
- Оценка размера выхода в GUI остаётся полной (точный кроп известен после выравнивания) — в примечании «стабилизация срезает края до пересечения кадров».

## Часть 3 — детектор медленного движения (пары кадров на расстоянии)

- `src/motion.rs`: помимо разности с референсом, для каждого кадра i считается разность с кадром i+K для K из адаптивного набора (K = n/4 и n−1; для 32 кадров это 8 и 31): решётка кадра i+K ресемплируется через композицию аффинных отображений решёток (T = A_{i+K} ∘ A_i⁻¹ — детерминированная композиция двух уже построенных аффинных карт), энергии блоков, **максимум** с энергией «против референса», дальше тот же порог/медиана/морфология. Объект с 0.5 px/кадр даёт 4 px на расстоянии 8 кадров — детектируется.
- Стоимость: ~2 дополнительных построения решётки на кадр (~60 мс каждая, параллелится) — суммарно <+2 с на серию из 32 кадров.
- Кадры за пределами серии (i+K ≥ n) пропускаются; для серий из 4 кадров K = {1?, 3} — n/4=1: минимум 2.

## Часть 4 — качество fallback-зон (паттерн Байера/ХА при приближении)

- В `run_band` добавляется отдельный аккумулятор веса опорного кадра → после нормализации пер-пиксельная доля `ref_share` (u8). В зонах, где она высока (движение замаскировано, слился почти только референс), деконволюция дожимается пропорционально доле — она больше не подчёркивает байеровскую решётку и каёмки ХА одиночного кадра.
- `MergeResult` это поле не покидает (внутренняя плоскость merge, u8 на выходную сетку).

## Тесты

- `tests/alignment.rs`: сдвиг 15 сенсорных px восстанавливается ≤0.02 px (раньше — провал); существующие тесты малых сдвигов не регрессируют.
- `tests/merge_synthetic.rs`: (a) серия с большими сдвигами (±10 px) — со стабилизацией выход = пересечение, PSNR внутри высок, без стабилизации старое поведение; (b) медленный объект (0.4 px/кадр): старый детектор пропускает, парный ловит, маскированное слияние лучше; (c) с `deconvolve=1` и движением hp-шум в маскированной зоне не выше, чем при `deconvolve=0` (гейт работает).
- Юниты `motion.rs`: парная детекция на синтетике с медленным квадратом.
