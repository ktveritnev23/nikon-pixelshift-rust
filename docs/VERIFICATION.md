# Верификация

Проверка идёт измеримо, а не «на глаз»:

1. **Сверка с NX Studio** по тем же исходным кадрам (`tools/validate.py`). Оба файла
   (наш DNG и эталонный .NEFX) декодируются независимо через LibRaw в линейный
   16-битный RGB, затем сравниваются: наилучший сдвиг, корреляция яркости, корреляция
   и усиление по каналам R/G/B, PSNR после подгонки усиления и отношение энергии
   высоких частот (средний модуль лапласиана на резком кропе 512x512).
2. **Сравнение с одиночным кадром** (`tools/resolution.py`): тот же участок для
   (а) одиночного кадра, увеличенного в 2 раза кубической интерполяцией, (б) нашего
   слияния, (в) эталона NX. Отношение лапласианов (б)/(а) — реальный прирост разрешения.
3. **Проверка читателями** (`raw-identify`, `dcraw_emu`, `tiffinfo`, ImageMagick, `sips`
   (ImageIO), rawler 0.6 — см. `docs/COMPATIBILITY.md`).

Полный прогон одной командой: `sh tools/accept.sh out`.

| 107NZ6_3 | 32 кадра, 2x | 12096x8064 | 15.7 с | 4.18 ГБ | 0.98669 | 18.7 / 18.7 / 14.9 | 0.980 | **1.89x** |

«Детализация к NX» — отношение энергии высоких частот на резком кропе 1:1 к эталону
NX Studio (1.0 = столько же). «Прирост к одиночному кадру» — во сколько раз больше
энергии высоких частот, чем у одиночного кадра, увеличенного в 2 раза.

Что это значит:

- Режимы 4/8 кадров практически совпадают с NX Studio по детализации (0.95-0.98) и
  полностью совпадают по геометрии/цвету (корреляция 0.996-0.9997).
- Режимы 16/32 дают реальное 97 МП изображение: 107 совпадает с NX (0.98), 106 отстаёт
  (0.62), но даёт в 3.3 раза больше высокочастотной энергии, чем апскейл одиночного кадра.
- Остаточный разрыв на 106 объясняется механикой именно этой серии: поворот до -279″
  (1.35e-3 рад) и дрейф внутри серии, остаток жёсткой модели до 0.65 px RMS по окнам.
  Даже при «идеальной» решётке 0.5 px наш оператор реконструкции даёт ~0.49 от NX без
  деконволюции и 0.63 с ней; чтобы поднять выше, нужен другой оператор (неотрицательное
  ядро + регуляризованное решение на нерегулярной решётке), это выходит за рамки выпуска.
- Прирост шума от деконволюции: +15 % в плоских областях (измерено), цветных каёмок на
  резких границах нет (встроенный ограничитель звона). При `--deconvolve 0` возвращается
  прежнее поведение (мягче, тише).

## Методические замечания

- Усиление по каналам между нашим файлом и эталоном NX одинаково для R, G и B (отличие
  < 0.2 %): NX тоже сохраняет данные без баланса белого, сравнение по каналам корректно.
- Абсолютные значения отличаются общим множителем (LibRaw масштабирует декодированный
  поток), поэтому PSNR считается после подгонки усиления по каждому каналу.
- Окно сравнения детализации выбирается по энергии градиента (иначе попадает на
  расфокусированный передний план).
- PSNR ограничен разницей тонкой структуры шума и реконструкции, а не ошибкой слияния:
  на текстуре 1:1 наш результат и NX отличаются прежде всего высокочастотной составляющей.
