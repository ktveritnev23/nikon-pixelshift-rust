# Совместимость выходных файлов

## Что изменилось в этой версии (после первых тестов пользователя)

Первые файлы не открывались в Capture One Pro и RapidRAW, а Preview показывал цветное
«зерно». Причины найдены и устранены:

1. **RapidRAW: ошибка декодирования.** Декодер RapidRAW (rawler) падал на проверке
   `assert_eq!(levels.len(), width*height*cpp)`: тег `BlackLevel` имел одно значение при
   `SamplesPerPixel = 3`. По DNG-спеке `BlackLevel`/`WhiteLevel` пишутся по значению на
   компонент. Теперь пишется по три значения, и файл декодируется.
2. **Preview: цветное «зерно».** Оно появлялось из-за компоновки: основное изображение
   лежало в SubIFD, а в IFD0 было маленькое 8-битное превью; ImageIO (движок Preview)
   принимал данные за мозаику и «демозаицировал» цветную картинку. Теперь основное
   изображение лежит в IFD0, превью — в IFD1 (8-бит RGB и JPEG). На 1:1-кропе разброс
   хроматического шума упал с 34.2 до 8.2 ADU — зерно ушло.
3. **Capture One: файл не виден.** Локально C1 нет, поэтому причина проверялась по
   эталону: на диске найден линейный DNG, созданный самой Capture One (Panorama Stitch)
   с той же камерой. У него та же компоновка (превью в IFD0 + linear raw в SubIFD), но
   цветовые теги лежат в IFD0, есть пара `ColorMatrix1`+`ColorMatrix2`, `ForwardMatrix`,
   `AnalogBalance`, `DNGPrivateData` и `OriginalRawFileName`, `DNGVersion 1.1.0.0`.
   Эти отличия реализованы в экспериментальном флейворе `c1`.

## Флейворы вывода

| Флейвор | Что пишется | Для кого |
|---|---|---|
| `linearraw` (по умолчанию) | 16-бит линейный RGB, PI=34892, полное цветовое разрешение | Lightroom/ACR, LibRaw-инструменты, RapidRAW (после фикса BlackLevel) |
| `cfa` | мозаика Байера 16 бит (PI=32803, RGGB), редактор демозаицирует | максимальная совместимость: RapidRAW, Capture One, darktable, RawTherapee, Adobe |
| `c1` (экспериментальный) | диалект, снятый с файла самой Capture One | проверка импорта в Capture One |
| `rgb` (экспериментальный) | PI=2, 16 бит RGB | ни один из проверенных читателей его не принимает; оставлен для диагностики |
| `--format tiff --tiff-render` (по умолчанию для TIFF) | 16-бит sRGB TIFF, гамма и матрица применены | универсальный выход: Capture One, Preview, любые редакторы |
| `--format tiff --tiff-linear` | 16-бит линейный TIFF (camera native) | когда нужны именно линейные данные без DNG-метаданных |

## Линзовые метаданные

Во все флейворы пишутся `LensModel` (0xA434), `LensSpecification` (0xA432),
`FocalLengthIn35mmFilm` (0xA405), `MaxApertureValue` (0x9205, APEX максимальной диафрагмы
объектива) и `LensMake` (0xA433), если он есть в исходном NEF (Nikon для сторонних
объективов его не пишет, поэтому «придумывать» мы не стали). Это позволяет Lightroom и
Capture One подобрать собственный профиль объектива автоматически. Для объективов без
профиля (например Viltrox AF 135/1.8 LAB Z) в программе есть собственная коррекция
дисторсии (`--distort K1[,K2]` / ползунок в GUI).

Дополнительно к линзовым тегам в DNG теперь пишется **настоящий Exif IFD** (`0x8769`) и в нём
— копия **maker note исходного NEF** (тег `0x927C`, байт-в-байт, 231 314 байт для 32-кадровой
серии; отключается флагом `--no-makernote`). Именно по этой проприетарной идентификации
Capture One строит свой `LensIdGuid`: у NEF и .NEFX он один и тот же, а у нашего DNG до этой
правки был другим («пустой» профиль с `LensGeoAbr ... |0.000000` — коррекция выключена).
Заодно исправлен `LensSpecification`: раньше для зума писался вырожденный (24,24,4,4), теперь
реальный диапазон (24,120,4,4), плюс `BodySerialNumber`/`LensSerialNumber`.

Наш файл по геометрии совпадает с результатом NX Studio (измерено: ≤0.2 px по 24 блокам,
k1 ≈ 3e-6), то есть ни NX, ни мы не зашиваем коррекцию в файл: видимая подушкообразность —
это дисторсия объектива, которую редактор компенсирует только если знает объектив.
## Почему Capture One не применяет коррекцию к нашему DNG

Проверено на C1 16.8 и на файлах настроек самой C1 (`<серия>/CaptureOne/Settings1680/*.cos`):

- для NEF и для `.NEFX` от NX Studio C1 показывает «Manufacturer Profile»: это данные
  коррекции, которые Nikon зашивает в сам RAW-файл (плюс собственный `LensIdGuid` C1);
- в C1 нельзя вручную выбрать профиль ни для одной Z-линзы, кроме 24-70mm f/4 S — то есть
  для этих объективов C1 не пользуется своей базой профилей, а полагается на данные
  производителя внутри RAW;
- у нашего DNG этих данных нет и быть не может: мы пишем стандартный DNG, а C1 не читает
  Nikon-овскую служебную информацию из DNG (даже когда мы копируем maker note байт-в-байт —
  проверено). В `.cos` для нашего файла C1 создаёт пустой профиль с нулевой коррекцией.

Вывод: заставить C1 применить профиль к нашему файлу нельзя — коррекцию надо запекать в
изображение. Для этого в программе есть трёхчленная модель дисторсии (`--distort K1[,K2[,K3]]`,
ползунки в GUI) и автоматический подбор коэффициентов по эталонному изображению
(`--distort-fit corrected.tif`, кнопка «Fit distortion from reference…»): эталон делается
экспортом одного кадра из C1 с включённым «Manufacturer Profile».
## Что выбрать

- Lightroom / Adobe Camera Raw: `linearraw` — полное цветовое разрешение, демозаики нет.
- Capture One: если `linearraw` не импортируется — `cfa` (яркостная детализация сохраняется,
  цветовое разрешение отдаётся демозаике редактора) или `--format tiff` (гарантированно
  открывается, но это уже не RAW).
- RapidRAW: `linearraw` (после фикса) или `cfa`.
- Просмотр в Preview/Quick Look: `cfa` или TIFF; линейный DNG в Preview корректно
  показывается, но Apple не применяет к нему свою RAW-обработку.

## Почему не «один формат для всех»

Линейный DNG (PI=34892) — единственный способ отдать полное цветовое разрешение режимов
4/8 кадров и убрать демозаику из пайплайна редактора. Но его поддержка неодинакова:
LibRaw/rawler/Adobe его читают, ImageIO и часть проприетарных редакторов — нет.
Мозаичный DNG (CFA) читают все, но редактор снова демозаицирует, и цветовое разрешение
падает до обычного Bayer-уровня. Поэтому флейвор — это выбор пользователя, а не дефект.
