# nikon-pixelshift-rust — слияние Nikon Pixel Shift в линейный DNG

Программа для macOS/Linux (Rust + egui), которая собирает серию кадров Nikon Pixel Shift
(4, 8, 16 или 32 снимка) в одно изображение высокого разрешения и сохраняет его в
**линейный DNG** (или 16-битный TIFF), пригодный для дальнейшей обработки в Lightroom /
Adobe Camera Raw и Capture One — без NX Studio, регистрации и VPN.

## Зачем

Камера (Nikon Z6 III и другие модели с Pixel Shift) снимает серию кадров, в которых IBIS
сдвигает матрицу на доли пикселя, но не умеет склеивать их сама. NX Studio умеет, но
требует учётной записи, а его выходной формат `.NEFX` не читается сторонними
редакторами. `pixelshift` выполняет ту же работу и пишет результат в стандартный DNG.

## Что получается на выходе

| Режим камеры | Кадров | Выход | Что это даёт |
|---|---|---|---|
| 4 снимка | 4 | 6048x4032 (24 МП), полный RGB в каждом пикселе | полное цветовое разрешение без демозаики |
| 8 снимков | 8 | 6048x4032 (24 МП), полный RGB | то же + шумоподавление (усреднение дублей) |
| 16 снимков | 16 | 12096x8064 (97 МП) | сетка отсчётов вдвое плотнее по каждой оси (4x пикселей) |
| 32 снимка | 32 | 12096x8064 (97 МП) | то же + шумоподавление |

Сдвиги кадров программа измеряет сама по содержимому (субпиксельная точность), а не
берёт из метаданных: Nikon не записывает их в файлы, и реальные сдвиги всегда чуть-чуть
отличаются от идеальных.

## Установка

Нужны: macOS или Linux, Rust (проверено на 1.99) и LibRaw.

```sh
brew install libraw          # macOS
# sudo apt install libraw-dev  # Debian/Ubuntu

cargo build --release
./target/release/pixelshift            # графический интерфейс
./target/release/pixelshift --help     # командная строка
```

LibRaw — единственная системная зависимость; она нужна для декодирования NEF
(собственный декодер Nikon — это недели работы и главный риск для совместимости).

## Командная строка

```sh
# каталог с серией: режим определяется по числу кадров, имя файла — автоматически
pixelshift merge 106NZ6_3 --out /path/to/result.dng

# список файлов + TIFF вместо DNG
pixelshift merge a.NEF b.NEF c.NEF d.NEF --format tiff --out result.tif

# что программа видит в серии: камера, режим, сдвиги по кадрам, ожидаемый размер
pixelshift inspect 107NZ6_3

# принудительно 2x-сетку и запись «уменьшенного» варианта рядом
pixelshift merge 106NZ6_3 --scale 2 --also-1x
```

Флаги: `--out`, `--dng-flavor linearraw|cfa|rgb`, `--format dng|tiff`,
`--tiff-render` (по умолчанию для TIFF: баланс белого + матрица камеры + гамма sRGB) или
`--tiff-linear` (camera-native линейные данные), `--deconvolve 0..2` (компенсация ядра
реконструкции, по умолчанию 1.0), `--distort K1[,K2]` (коррекция дисторсии объектива,
по умолчанию 0), `--also-1x`, `--no-align`, `--threads N`, `--quiet`.
Имя файла по умолчанию: `<имя первого кадра>_pixelshift_<scale>x.dng`.
По умолчанию имя файла: `<имя первого кадра>_pixelshift_<scale>x.dng` рядом с исходниками.
Прогресс печатается в stderr, итоговая сводка — в stdout.

## Форматы вывода и совместимость

| Что писать | Кому | Цена |
|---|---|---|
| `--dng-flavor linearraw` (по умолчанию) | Lightroom/ACR, RapidRAW, LibRaw-инструменты | полное цветовое разрешение; часть редакторов (Capture One) такой DNG не импортирует |
| `--dng-flavor cfa` | Capture One, RapidRAW, darktable, RawTherapee — всё, что работает с обычным Bayer-RAW | редактор сам демозаицирует: цветовое разрешение падает до обычного Bayer-уровня, яркостная детализация сохраняется |
| `--format tiff` (sRGB) | любое приложение, включая Preview | это уже не RAW: тональность и цвет зафиксированы |

Подробная матрица «читатель x формат» и объяснение ограничений — `docs/COMPATIBILITY.md`.
Если файл не открывается в вашем редакторе: сначала `--dng-flavor cfa`, затем `--format tiff`.
## Дисторсия и профиль объектива

Наш результат — «сырая» геометрия кадра: программа только выравнивает кадры друг
относительно друга и не применяет оптическую коррекцию. Проверено измерением: наш файл
совпадает по геометрии с результатом NX Studio (по 24 блокам расхождение не более 0.2 px,
радиальный коэффициент k1 ≈ 3·10⁻⁶, residual 0.01 px) — то есть NX тоже не зашивает
коррекцию в файл. Подушкообразность, которая видна при прямом сравнении, — это дисторсия
самого объектива.

Редакторы компенсируют её сами, если могут определить объектив: для NEF у Capture One есть
данные камеры/профиль, а для нашего DNG их не было. Теперь программа пишет линзовые EXIF —
`LensModel`, `LensSpecification`, `FocalLengthIn35mmFilm`, `MaxApertureValue`, `LensMake`,
`BodySerialNumber`, `LensSerialNumber`, а также копия maker note исходного NEF (тег 0x927C,
отключается `--no-makernote`) — по ним Lightroom и Capture One подбирают профиль объектива
так же, как для NEF.

Если профиля нет (как у Viltrox AF 135/1.8 LAB Z), используйте собственную коррекцию:
ползунок «Distortion k1» в GUI (живое превью, при экспорте пишется то же значение) или
`--distort K1[,K2]` в CLI. Модель Брауна: `r' = r·(1 + k1·r² + k2·r⁴)`, r = 1 в углу кадра;
положительное k1 убирает подушкообразность, отрицательное — бочку. Модель трёхчленная
(`r' = r·(1 + k1·r² + k2·r⁴ + k3·r⁶)`), диапазон ползунка и `--distort` — ±0.06 по каждому
члену; для NIKKOR Z 24-120mm на 24 мм измеренная бочка ≈4 %, то есть `--distort -0.04`.
`--distort 0` — прежний результат бит-в-бит; коррекция 24 МП стоит ~0.2 с, 97 МП — ~1 с.

**Подбор коэффициентов по эталону (рекомендуется).** В Capture One включите для одного кадра
серии «Lens Correction → Manufacturer Profile» и экспортируйте его в 16-битный TIFF (сжатие
None или Deflate — LZW наш читатель не понимает), затем:

```sh
pixelshift merge 108NZ6_3 --distort-fit corrected_frame.tif --out result.dng
```

Программа измеряет поле смещений по 80 блокам кадра (пирамидальное сопоставление +
субпиксельный Гаусс—Ньютон), подгоняет k1,k2,k3 и печатает коэффициенты, сдвиг и остаток
(RMS в пикселях). В GUI это кнопка «Fit distortion from reference…». Нормировка на половину
диагонали делает коэффициенты независимыми от масштаба, поэтому подбор на 1x применим к 2x.
Точность (проверено на независимом синтетическом эталоне): k1 восстанавливается с ошибкой
~1.5 %, суммарная коррекция в углу — в пределах ~3 %; остаток RMS показывает, хватает ли
трёх членов (для ровной бочки — да; если остаток велик, у объектива есть тангенциальная
составляющая, и её надо моделировать отдельно).
## Графический интерфейс

1. Перетащите каталог с серией (или выберите «Open folder…»): программа найдёт все
   Pixel Shift серии в каталоге.
2. Проверьте панель кадров: там видны измеренные сдвиги, ISO и выдержка. Если сдвиги
   выглядят хаотично — кадры сняты не в режиме Pixel Shift или это другая серия.
3. В панели Options выберите масштаб (для 4/8 кадров — 1x, для 16/32 — 2x),
   формат (DNG/TIFF) и нажмите «Merge».
4. Превью можно масштабировать колесом и панорамировать мышью. При увеличении программа
   сама догружает деталь видимой области в полном разрешении (базовое превью 2048 px +
   кропы по требованию, индикатор «loading detail»), поэтому на 100 % видно реальное
   качество, а не растянутое превью.
5. Ползунок «Distortion k1» компенсирует дисторсию объектива с живым превью; при экспорте
   применяется то же значение (см. раздел «Дисторсия и профиль объектива»).
6. «Save…» записывает результат; для нескольких серий есть пакетная очередь.

## Что делать с DNG в редакторе

- Данные в DNG — **линейные, в родных координатах камеры, без баланса белого**;
  баланс белого (as shot) записан в метаданных, поэтому Lightroom/ACR и Capture One
  открывают файл с правильным цветом без ручных множителей.
- Профиль цвета — `ColorMatrix1` из метаданных камеры. Это «математический» профиль,
  а не Adobe Camera Standard: при желании постройте профиль под камеру в редакторе.
- Разрешение и цвет уже «слиты» — демозаики не будет, картинка сразу линейная,
  к ней применимы обычные инструменты (экспозиция, кривые, цветокоррекция).
- Если ваш редактор не открывает линейный DNG (редко), используйте `--format tiff`
  (16-битный RGB TIFF открывают все).

## Точность (измерено, см. docs/VERIFICATION.md)

Все четыре серии прогнаны на M4 Pro и сверены с результатом NX Studio по тем же кадрам:

| Серия | Выход | Слияние | Пик RAM | Корреляция с NX | Детализация к NX | Прирост к одиночному кадру |
|---|---|---|---|---|---|---|
| 4 кадра | 6048x4032 | 2.0 с | 1.39 ГБ | 0.9997 | 0.98 | — |
| 8 кадров | 6048x4032 | 3.5 с | 1.39 ГБ | 0.9958 | 0.95 | — |
| 16 кадров | 12096x8064 | 10.4 с | 3.40 ГБ | 0.9847 | 0.62 | **3.31x** |
| 32 кадра | 12096x8064 | 15.7 с | 4.18 ГБ | 0.9867 | 0.98 | **1.89x** |

«Прирост к одиночному кадру» — во сколько раз больше энергии высоких частот, чем у
одиночного кадра, увеличенного в 2 раза: 3.3x означает, что 97 МП — это не апскейл, а
реально восстановленные детали. Картинки для визуальной проверки:
`out/detail_107_single_vs_merge_vs_NX.png`, `out/detail_106_merge_vs_NX.png`.

Честно о разнице с NX Studio: на режимах 4/8 кадров и на 32 кадрах мы совпадаем
практически полностью (0.95-0.98 детализации), а серия 106 (16 кадров) отстаёт (0.62) —
именно в ней механика отработала с большим поворотом (до 279″) и дрейфом. Причина измерена:
дефицит не в выравнивании, а в операторе реконструкции — чтобы поднять 106 выше, нужен
другой оператор (неотрицательное ядро, регуляризованное решение на нерегулярной решётке).

Компенсация ядра реконструкции (`--deconvolve 1.0`, по умолчанию) подняла детализацию
106 с 0.44 до 0.62 и прирост к одиночному кадру с 2.36x до 3.31x; цена — +15 % шума в
плоских областях. `--deconvolve 0` возвращает более мягкий, но более «чистый» результат.
## Ограничения

- Сцена должна быть статичной: Pixel Shift — это штативная съёмка. Движущиеся объекты
  дадут артефакты (ghosting); маскирование движения в этой версии не реализовано.
- Сдвиги измеряются по изображению; при сильном шуме или очень низком контрасте
  оценка может быть неточной — тогда используйте `--no-align` или проверьте панель сдвигов.
- Несжатый DNG 97 МП занимает 558 МиБ, 24 МП — 140 МиБ (16-битный RGB), TIFF — столько же.
  Сжатие в этой версии не используется: 16-битный Deflate внутри DNG не читает LibRaw 0.22,
  то есть такой файл нельзя независимо проверить, а несжатые данные гарантированно
  открываются везде. Флаг `--compression deflate` принимается, но выводит пояснение и
  пишет файл без сжатия.
- Поддержка конкретных камер ограничена тем, что умеет LibRaw (Z6 III поддерживается
  версией 0.22.2 и новее).

## Как это работает

1. **Декодирование**: каждый NEF читается LibRaw через тонкий C-шим, берётся активная
   зона 6048x4032, чёрный уровень, CFA, баланс белого и цветовые матрицы.
2. **Выравнивание**: субпиксельный сдвиг каждого кадра относительно первого оценивается
   по содержимому (целочисленный поиск + градиентное уточнение), точность ~0.01-0.05 px.
3. **Слияние**: каждый сэмпл кадра переносится в точку выходной сетки
   `(k*(x + dx), k*(y + dy))` (k = 1 или 2) и раскладывается по 4 соседним пикселям
   билинейными весами в аккумулятор своего цвета; итог — `acc / вес`. При идеальных
   сдвигах ядро вырождается в дельту, и каждый выходной пиксель получает ровно R, G, G, B;
   дублирующиеся позиции режимов 8/32 усредняются (это и есть шумоподавление).
4. **Запись**: линейный DNG (PhotometricInterpretation = LinearRaw, 16 бит, три канала,
   метаданные камеры) или 16-битный TIFF.

Подробности: `docs/ARCHITECTURE.md`. Границы работ и приёмочные критерии: `docs/TASKS.md`.

## Разработка

```sh
export CARGO_HOME=$PWD/.cargo-home CARGO_TARGET_DIR=$PWD/.cargo-target
cargo test                 # unit + интеграционные тесты (используют реальные NEF)
cargo build --release
tools/validate.py OUT.dng --ref 106NZ6_3/_DSC0534_merged.NEFX   # сверка с NX Studio
```

Структура: `src/rawio` (LibRaw + C-шим), `src/shift.rs` (выравнивание),
`src/merge.rs` (реконструкция), `src/write` (DNG/TIFF), `src/app` (egui), `src/cli.rs`.
